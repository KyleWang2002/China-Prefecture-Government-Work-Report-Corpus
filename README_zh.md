# 中国地级市政府工作报告语料库

[English README](README.md)

这是我独立整理的中国城市政府工作报告语料项目。当前工作总表包含 **295 个城市序列、31 个省级行政区**，包括四个直辖市。主体年份是 **2003-2026 年**，少数城市更早。

这个项目最初只是为了论文找数据。真正开始一座城市、一座城市往前补以后，我发现最费时间的不是爬网页，而是判断“这份报告到底还在不在”、旧网站为什么没有、年鉴里能不能补回来、扫描件怎样恢复阅读顺序，以及行政区划变化以后某个 city-year 到底应该算缺失还是本来就不存在。

![逐年覆盖](figures/coverage_by_year.png)

## 当前规模

- **295** 个城市序列
- **31** 个省级行政区
- 当前总表 **295/295** 已完成一轮人工核对
- 记录区间内 **6,716** 个 city-year 标记为 available
- 记录区间内 **32** 个明确缺口
- 单独整理 **64** 条 2000-2018 年地级层面行政区划变更
- 当前总表跨度：**2000-2026**

这些数字描述的是我目前的项目总表。它不等于“所有文件都来自市政府官网”，也不代表我在这里声称自己一定是所有商业/非公开数据库里最全的。

## 为什么政府工作报告值得做

市级政府工作报告通常由市长在当地人民代表大会年度会议上作报告，回顾上一年度工作，同时说明新一年的主要目标、任务和政策重点。因为这种文件按年重复出现，而且内容同时包含回顾和前瞻，它很适合做政策关注、发展目标、产业政策、环境政策等城市层面的长期文本研究。

但这个文本不能脱离制度背景理解。宪法规定地方各级人民代表大会是地方国家权力机关，地方各级人民政府是地方国家权力机关的执行机关和地方国家行政机关，并向本级人民代表大会负责并报告工作；地方组织法进一步规定，县级以上地方人大听取和审议本级人民政府工作报告。详细说明见 [`docs/institutional_background.md`](docs/institutional_background.md)。

## 这个项目真正难在哪里

### 1. 官网没有，不等于报告不存在

很多市政府网站只保留近几年，旧网页会因为改版、迁移或历史系统下线而消失。因此我的处理原则一直不是“官网搜不到 = 缺失”。

最典型的是 **广西来宾**。2025 年有研究者向来宾市政府询问 2011-2014 年政府工作报告，官方回复明确表示：因为网站系统数据迁移，现暂无法提供 2014 年及以前的电子版，2015 年以后可在门户网站查询。

但我后来从《来宾年鉴》中把 **2005-2014 年**的报告补了出来。仓库里用 2010 年报告做一个完整案例。

见 [`docs/case_studies/laibin_archive_recovery.md`](docs/case_studies/laibin_archive_recovery.md)。

### 2. 老 PDF 不是“另存为 txt”就结束了

历史文件有 HTML、Word、文字 PDF、扫描 PDF、图片和年鉴页面。中文双栏/多栏尤其容易把顺序打乱。

**临沂 2010 年政府工作报告**收录在《临沂年鉴 2011》中，是一个很典型的双栏案例。普通 PDF 提取可能把左右栏交叉在一起；我原来的工作代码用过 PyMuPDF、CnOCR、PaddleOCR，并对两栏/三栏做切分。现在仓库里的代码是把这些零散 notebook 重写成了相对干净、可复用的版本。

见 [`docs/case_studies/linyi_multicolumn.md`](docs/case_studies/linyi_multicolumn.md)。

### 3. 有些网站其实很好抓

如果一个城市把历年报告整齐放在 HTML 列表页里，那么完全没必要“为了复杂而复杂”。这种情况下就是发现链接、逐页抓正文、清理、按年份保存。仓库保留了一个通用 HTML collector，但**不会公开我逐个城市积累的原始链接总表**。

见 [`docs/case_studies/standard_html_collection.md`](docs/case_studies/standard_html_collection.md)。

### 4. 行政区划变化不是附属问题

城市面板里，“没有这一年”可能有两种完全不同的原因：报告没找到，或者这个地级市当年根本还没以当前形式存在。

因此我另外整理了 **64 条 2000-2018 年地级层面行政区划变化**，包括撤地设市、撤盟设市、城市更名、新设地级市、撤销地级市等。

## 公开什么，不公开什么

这个仓库不是把全部语料和全部来源链接直接倒出来。

公开：
- 城市级和 city-year coverage；
- 行政区划变更表；
- 处理、清洗、核验代码；
- 少量案例文本。

暂不公开：
- 我逐个城市整理的 source-link 总表；
- 年鉴、报纸等完整原始扫描件；
- 申请阶段的完整全文语料。

原因很简单：source-link 表本身也是长期维护这个数据库的工作资产，而且很多历史来源的再分发条件并不一样。

## 代码说明

`src/` 不是把我以前所有 notebook 原样上传。原来的代码有很多绝对路径、临时变量、针对某个网站的选择器，直接公开反而没意义。

现在的版本做了三件事：

1. 保留真正用过的技术路线；
2. 删除本地路径和 city-specific source URL；
3. 把常用流程重写成可以复用的模块。

另外加了一个 `llm_assisted_review.py`。它只负责把可疑 OCR 片段整理成人工审核包，不会自动覆盖文本。这个模块是整理 GitHub 时把我原先“人工 + 大模型辅助判断”的思路正式化，不应该理解成“历史上每一份报告都跑过同一段 LLM 代码”。
